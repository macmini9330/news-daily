# 日报日期/窗口/时区 — 三合一调试记录（2026-08-20）

用户对日期逻辑纠偏两次，最终定案。本文记录完整演进与验证方法，避免第三次走弯路。

## 用户两次纠偏

1. **第一次（投诉）**：「首页的8月20日点进去之后标题下方写的又是8月19日，你就不能做个全面的检查吗，怎么这么多低级错误」
   - 当时状态：文件名=发布日（8-20），页面标题=新闻日期（8-19），不一致。
   - 错误修复：把三者统一为「新闻主日期」→ 但用户又问...

2. **第二次（再纠偏）**：「今天是8月20日，为什么最新一期是8月19日的，这个逻辑你觉得合理吗？」
   - 用户直觉：**今天生成的日报就该叫今天**。新闻主日期命名让他觉得「总慢一天」。
   - **最终定案（用户原话）**：「今天早上9点生成的日报应该是8月20号的日报... 8月20号的日报收集的内容是8月19日早上9:00~8月20日早上9点的新闻内容。这个时间指的是北京时间。然后另外加一条备注...详情页的最上方要说明一下本次日报的涵盖的时间范围。」

## 最终规则

| 项 | 值 |
|----|----|
| 文件名 | 发布日（运行日）`2026-08-20.html` |
| 页面标题 | `2026年8月20日日报` |
| 首页显示 | 发布日（自动=文件名） |
| 内容范围 | 前一日 09:00 → 当日 09:00 |
| 时区 | **北京时间**（全链路统一） |
| 页顶说明条 | window-bar：「本日报抓取新闻时间范围：2026年08月19日早9:00至2026年08月20日早9:00（北京时间）」 |

## 时区验证方法（重要）

哈通社显示的是**阿斯塔纳时间 UTC+5**，系统是**北京 UTC+8**。验证：
```python
# 抓 lenta 最新时间 vs 当前系统时间
times = re.findall(r'<time class="meta-date">([^<]+)</time>', html)
# 例：哈通社 13:11 vs 北京 16:13 → 差 3h 整 = 纯时区差
```
若差 3h 整 → 时区；若多出几分钟 → 发布延迟。结论：`parse_time` 后统一 `+timedelta(hours=3)`。

**转换要在源头（fetch 层）做一次**，全链路（窗口过滤 + 页面展示）就都统一了，不要在 generate 再转。

## 窗口双向过滤

`window_bounds()` 返回 `(start, end)`，两处过滤都要判断：
```python
if at < start or at > end:  # 只判 start 会混入当天 9:00 之后的新闻
    continue
```
