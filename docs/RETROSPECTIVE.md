## 四、通用教训（跨项目可复用 ⭐）

### A. 流水线 / 定时任务

1. **双层超时陷阱（最贵教训）**：嵌套 subprocess 流水线（cron 外层 → 脚本内层），超时必须**内外层同时放宽**——8/22 只改外层，8/24 又被内层杀。定案：内层 analyze 1800s + 外层 2400s。**超时上限 ≥ 实测耗时 × 1.5，且按最坏情况（断电补跑 3 倍量）设计**。
2. **stdout 缓冲陷阱**：Python stdout 重定向到文件/管道时全缓冲，日志无输出 ≠ 卡死。**判断进程是否工作：`ps` CPU 时间增长 + `lsof -p PID -i` 看 ESTABLISHED 连接**（有=在调 API）。
3. **catch-up 补跑**：Hermes cron 断电错过会自动补跑（开机后 ~1 分钟）。但补跑抓**整个窗口**导致条数暴增 3 倍——超时/成本设计要按最坏情况。
4. **质量检查门禁**：生成后、发布前必须过检查（文件存在/大小/条数范围/空标题/乱码/截断），**失败终止+通知管理员**，不把坏内容推给用户。
5. **cron no_agent 模式**：纯脚本直跑（LLM 不参与指令理解）消除跑偏；stdout 全文即投递内容，别 print 过程日志。
6. **薄包装转发**：cron script 相对路径解析到 `~/.hermes/scripts/`，用薄包装 `runpy.run_path` 转发到项目真实脚本，单一来源。
7. **外部依赖失败不阻断**：可选数据（汇率）抓取失败不阻断主流程（`run_step` 失败继续）。

### B. LLM 集成

8. **分类返回顺序不受控**：LLM 返回顺序≠输入顺序，需要排序的业务在**生成层显式 sort**（板块内按时间降序）。
9. **无上限逻辑是隐性缺陷**：分类 prompt 只写「输出相关」不写数量约束 → 选举日+全窗口叠加爆 178 条。**需要稳定条数就必须显式上限**（候选：输入预过滤 + 分类上限 + 同类合并）。
10. **LLM JSON 输出防御**：解析后检查类型（dict/list），缺失板块兜底。
11. **temperature/max_tokens 固化**：temperature=0.2、分类 10000/翻译 4000，防漂移。
12. **两阶段处理**：先批量分类（一次处理全部），再逐条详情翻译（耗时大头）——耗时随条数线性增长。

### C. 飞书集成

13. **batch_get_id 响应是扁平结构**：`data.user_list[]` 每项直接含 `user_id` 字段（`user_id_type=open_id` 时值即 open_id），**不是** `user_list[].users[].open_id`。用旧格式解析会误判「查不到」，误导排查方向（王晶首次查到是误打误撞）。**必须 POST**（GET 返回空）。
14. **open_id 按应用隔离**：同一用户在不同应用下的 open_id 不同，必须用目标应用的凭证查询。
15. **独立缓冲机器人模式**：企业推送用独立应用机器人（非主 bot），权限最小化（只开 im:message），不配置事件订阅=纯单向推送无对话框；版本可用范围控制可见性（范围外人搜不到）。**解决「用户与助手建渠道的权限混乱」担忧**。
16. **卡片样式**：interactive 卡片 = header（template=blue 正常/red 告警）+ 文本 + 按钮（url 跳转）+ note；失败场景用红色告警卡只发管理员。
17. **通讯录数据权限范围 ≠ 版本可用范围**：两者都要配置，权限开了但查不到人通常是数据权限范围没含目标。

### D. 诊断方法

18. **全链路核对**：改日期/命名/计数类逻辑必须全链路验证（抓取窗口→文件名→页面标题→首页列表→计数→时间范围），一处不一致就交付会挨骂（用户「你就不能做个全面的检查吗」）。
19. **重构后必须端到端实测**：只 py_compile 就交付会漏 bug（sys.path、变量名大小写、包前缀）。自查：静态检查 → 分步运行 → 完整流水线。
20. **断电定位**：心跳日志（JSONL 每 5 分钟）+ GAP 自动检测 + executions.db 缺失 tick = 精确断电窗口。

### E. 用户协作（本项目行为准则）

21. **数据先给原始**：报告结论前先展示原始检索结果/分布/排名。
22. **预测前先找反面因素**：不单向乐观。
23. **每个决策由用户拍板**：遇选择点先列选项等决定，不自行推进（「你着什么急啊」是强信号）。
24. **不可逆操作前备份+推演+等授权**。
25. **归档三刷新**：任务完成后 CHANGELOG + 技能 + 记忆同步更新。
26. **审美要求**：日报站「有设计感」是硬要求；排版不满意先搜业界参考再改。
